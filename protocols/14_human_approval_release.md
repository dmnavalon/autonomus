# 14 — Aprobación humana y release

**Aplicación**: Obligatorio para Coordinador, Final Verifier, Notificador, GitHub Operator
y Guardian.

## Reglas

1. El sistema solo deja PR listo; el humano decide merge.
2. El mensaje final permitido NO promete cero errores: debe decir que no se detectaron
   errores bloqueantes.
3. Producción, `main`, billing, secrets y cambios destructivos requieren aprobación humana.
4. El PR debe contener resumen, alcance, tests, riesgos y links de evidencia.
5. Si hay duda crítica, detener y pedir decisión.

## Frase canónica (estado terminal de éxito)

`"No se detectaron errores bloqueantes en QA automático. Listo para revisión humana. Preview: <url>. PR: <url>."`

## Frase canónica (estado terminal de falla)

`"La fábrica no pudo cerrar el ciclo automático. Revisa el Issue #<n> en GitHub. Razón: <causa>."`

## PR body obligatorio

```markdown
## Objetivo
<una oración del Planificador>

## Alcance
- bullet 1
- bullet 2

## Fuera de alcance
- ...

## Tests
- E2E: e2e/factory/<nombre>.spec.ts
- Resultado: passed | failed

## Riesgos
- ...

## Evidencia
- Issue: #<n>
- Preview: <url>
- QA report: <artifact_url>

> Generated by Autonomus factory. Do NOT auto-merge.
```

## Branch protection (requerido en `main`)

- PR requerido (no push directo).
- Status checks: `ci-quality`, `factory-tests`, `qa-playwright`.
- ≥ 1 review humana antes de merge.
- No force-push.
- No `admin` bypass.

## Anti-patrones

- Auto-merge de PR generado por la fábrica.
- Mensaje al usuario que afirma "todo está perfecto".
- Saltar Verificador Final.
- Aprobar humanamente desde un agente.
